### ⚠️ 部署降级警告：AMD Radeon 免费通道的 deepseek 不可用于验收（2026-09-08）

用户接入 developer.amd.com.cn/radeon（AMD GPU Cloud "Limited Free"）的
DeepSeek-V4-Flash-Vision-Exp，26 题两轮独立跑批均为 **48%**（性质命中 ~89%），对比
r1（opencode 部署）的 88% 剧烈下滑。证据链：
- 逐题对比：**9 题在 r1 通过、AMD 轮挂掉**（跨 A/B/C/D 全题型），反向仅 1 题
- 零请求失败、无截断、无压缩降级触发——排除通道问题，是模型输出本身读错
  （系数/点位级误读，如把 y=-x²+3x+4 的题画成完全不同的抛物线结构）
- 直读测试中该部署把第二支抛物线的常数项读错

**结论**：同名模型在不同部署间质量差异巨大（疑似量化/降配服务）。验收矩阵的
"模型"维度必须绑定部署质量——r2/r3 需与 r1 同质量通道（opencode 充值或其他
完整精度部署）才有可比性。本次发现本身是验收量具价值的实证：换模型供应商时
若无 26 题基准+多轮跑批，这类降级部署会被静默接受。

### glm r1 期间的通道战役（工程副产品）

分销商 glm 上游当天三次故障，逐层定位并修复（全部已入库）：
1. **进程层**：后端 5000 死亡重启；bench_run 增加错误事件自动重试（余额类永久错误除外）
2. **载荷层**：上游对大请求体直接掐断连接（全尺寸探针 349s 被切、41KB 也被 reset、
   tiny 探针畅通；hy3 同图正常）→ 适配器增加原图→1400px→1000px 三档降级重试
3. **输出预算层**（真正的根因）：**不带 max_tokens 的请求被网关掐断**（隐含无限输出额度）；
   补 4096 后推理模型的思考又吃满预算导致正文为空 → 增加"空正文+length 截断"自动
   升级重试（max_tokens=16384 + reasoning_effort=low，实测 22s 出全文）
4. **度量层**：bench_run 本地读超时 900→1800s；新增全载荷探针与恢复感知看门狗

## 关键结论

1. **跨厂商泛化成立**：deepseek-v4-vision 与 qwen3.8-flash 同一 prompt 体系下 r1 持平（88% vs 88%），
   证明 P1 范例带教式 prompt 已摆脱对特定厂商的过拟合（对比旧体系 Gemini 75% vs qwen 55% 的 20pt 差距）。
2. **deepseek r1 三例失败均为常规问题**（无链路/渲染 bug）：
   - `C-抛物线2`：conic_exists（圆锥曲线未建成）
   - `C-椭圆4`：point_at / slider_range / moving_point（定点+动点体系缺失）
   - `D-球1`：no_text（残留文字对象）
3. **glm-5.3-flash 探针良好**：A-二次函数1 满分 11/11（端到端含 P0 校验），具备验收价值。
   （历史记录：minimax-m3 中断前首例亦 11/11，后按用户决定移出名单）
4. **验证闭环全绿**：deepseek/minimax 两轮跑批 unknown_commands 遥测为空，P0 校验层稳定。
